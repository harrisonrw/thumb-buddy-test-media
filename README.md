# thumb-buddy-test-media

Scripts and a naming scheme for the video fixtures used to test
[Thumb Buddy](https://github.com/harrisonrw/thumb-buddy)'s thumbnail engine. Every file's name states its technical properties, so a test
can pick fixtures by name and check that what it probes matches.

```
action-sports/skatepark-kickflip__2160p_land_59.94fps_hevc_10bit_42s_hdr-hlg.mov
negative/truncated-moov-atom__1080p_land_30fps_h264_8bit.mp4
```

The full scheme, token vocabulary and a parsing regex are in
[docs/test-media-naming.md](docs/test-media-naming.md).

## Requirements

- Python 3.11 or later
- `ffmpeg` and `ffprobe` on the `PATH`

Some variants need encoders that not every ffmpeg build includes (`libx265`,
`libsvtav1`, `libvpx-vp9`). Variants whose encoder is missing are skipped and
reported.

## Media root

The scripts work on a media root: the directory holding the category
sub-directories (`action-sports`, `negative`, ...). It is the first of:

1. The command line: `rename-test-media.py <root>` or
   `generate-test-media.py --root <root>`.
2. The `TEST_MEDIA_ROOT` environment variable.
3. `root` in `config.toml` at the project root.
4. The project root.

To use a config file, copy the example and edit the path:

```sh
cp config.example.toml config.toml
```

```toml
root = "~/Media/thumb-buddy-test-media"
```

Relative paths are relative to `config.toml`, and `~` is expanded. The file is
git-ignored, so each checkout can point somewhere different.

## Scripts

### rename-test-media.py

Renames every file in each category sub-directory of the media root to match
the naming scheme, using what `ffprobe` reports. The slug (everything before
`__`) is kept, so re-running is safe. Fields that can't be determined are left
out.

```sh
scripts/rename-test-media.py            # dry run: show what would change
scripts/rename-test-media.py --apply    # rename
```

A rename is skipped if the target name is already taken. The `docs` and
`scripts` directories are never treated as categories.

### generate-test-media.py

Takes a short excerpt of one source clip and writes it out in many encodings,
so the content stays the same and only the technical properties vary. Each
output is named by probing it, so the names always match the scheme.

```sh
scripts/generate-test-media.py action-sports/skiing__*.mp4
scripts/generate-test-media.py clip.mov --groups matrix negative --start 12
scripts/generate-test-media.py clip.mov --list    # show what would be generated
```

| Group | Contents |
|---|---|
| `matrix` | Codec × bit depth: h264, hevc, av1, vp9, prores422, mpeg2 |
| `res` | Resolution ladder from 480p to 2160p, never above the source's size |
| `fps` | 23.976, 25, 29.97 and 59.94 fps |
| `variants` | Rotation, VFR, no audio, 4:2:2, 4:4:4, anamorphic, HDR tags, portrait and square crops |
| `negative` | Broken and misleading files: zero-byte, truncated, corrupt, audio-only, wrong extension |

All groups are generated by default. Outputs go in the source's directory
unless `--out` is given; the `negative` group always goes in
`<media root>/negative`. Existing files are never overwritten.

| Option | Default | Meaning |
|---|---|---|
| `--groups` | all | Groups to generate |
| `--start` | `0` | Excerpt start, in seconds |
| `--duration` | `5` | Excerpt length, in seconds |
| `--height` | `1080` | Short edge of the outputs, never upscaled; `0` keeps the source size |
| `--slug` | source's slug | Slug for the outputs |
| `--out` | source's directory | Directory for the outputs |
| `--root` | see [Media root](#media-root) | Media root |

The HDR variants are tagged as HDR without being re-graded: enough to exercise
HDR detection and tone-mapping paths, but the picture is not true HDR.
